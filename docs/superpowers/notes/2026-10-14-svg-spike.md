# SVG pane spike findings (2026-10-14)

Throwaway dev mod `office-spike`: a desktop Pane with an `<Svg>` scene (SMIL animation) and a 2 s timer that redraws the source. Observed by the person, then removed.

## Findings

### Round 1: single Svg, `isInteractive`, source changes every 2 s

1. SVG shows: yes.
2. Purple looping square: stays smooth across redraws.
3. Green one-shot square: not asked separately.
4. Flicker: bad flicker on each redraw.
5. Tooltip on hover: no.
6. "Redraws" counter keeps counting: yes (timer started in `session.start` works).

### Round 2: four Svgs in one probe

- A: interactive + changing source
- B: image mode (no `isInteractive`) + changing source
- C: interactive + static source
- D: image + static source

Results:

- Only A flickers. B, C and D do not.
- SMIL animation runs in image mode too (the B and D squares move).

## Decisions

- The office Svg is drawn in image mode (no `isInteractive`). Interactive mode with a changing source flickers; image mode does not.
- Hover tooltips never appear on this surface. Hover details become click-for-details: org chart rows are Buttons that show the agent's details below the chart.
- `FLUSH_MS` stays 350. The flicker came from interactive mode, not the redraw rate, so the 1000 ms fallback is not needed.
- Walk restarts on each redraw are handled by Task 6, which resumes walks from the current time.
- Stop conditions not hit: the SVG shows, and the timer-driven counter keeps counting.
- Side note: the spike's plugin.json named no `types` contract (a `contract.d.ts` file was added during the spike but never referenced from the manifest), so `claude plugin validate` reported `office-spike.ticks is not declared`. The engine still loaded and ran it. The real mod names its contract in plugin.json; confirm `plugin validate` accepts its state keys in Task 7.
